# Follow-up method — Follow-up message (DEFAULT)

The **default** post-meeting deliverable. Use for almost everything — 1-on-1s,
external calls, interviews, personal/EMS meetings, and buildpurdue meetings that are
not the weekly team meeting. (Only the buildpurdue **team meeting** uses
`team-recap.md` instead.)

Draft this after the meeting page is ingested and enriched (router `SKILL.md` Phase 8),
as **separate chat output — never inside the notes file**. Leave it **ready to send and
do not auto-send it** — the user reviews and sends it from the final delivery (Phase 10).

## What a good follow-up does
- Addressed to the **other party** (the person/people on the call), in the user's voice.
- Thanks them briefly (no fake gratitude), reflects the **most useful takeaway**, and
  names **1–2 specific points** from the conversation so it reads as genuinely personal.
- Includes a short, clear **ask / next step** if there is one (e.g. "send me X",
  "book a time here").
- Tone: concise, human, not over-polished. Short paragraphs or a few bullets.

## Notes
- One follow-up per recipient context. For a 1-on-1, it's a single message to that person.
- Keep it tight — a follow-up is a nudge + warmth, not a meeting-minutes dump (the notes
  page already holds the detail).
- The task/execution handling lives elsewhere — that's the shared `execution-split.md`
  step, which runs separately whenever the meeting has action items.
